# dsh-runninghub

[DSH Tavern](https://github.com/flizzywine/dsh-tavern) 插件：把本机的 [RunningHub](https://www.runninghub.ai/) 网关接进酒馆——在侧栏工作室里挑工作流、填提示词和参考素材，异步提交图片 / 视频任务，出片后自动下载并插进当前这局的正文。

## 安装

打开 DSH Tavern → 设置 → DSH Tavern → 插件，粘贴本仓库地址，点「安装」，刷新页面就能看到侧栏的 RunningHub 页；宿主侧代码更新后需要重启 DSH。连不上 GitHub 时，下载仓库 ZIP 在同一处点「上传 ZIP」。

装完在面板里填网关地址和 Key（默认 `http://127.0.0.1:6888`）。Key 存进 DSH 的凭据服务（`credentials`），不写进插件文件夹，也不会下发给浏览器。

不需要 `npm install`：插件没有运行时 npm 依赖，`client.js` 用到的 React 由 Tavern 的模块加载器提供。

## 要准备什么

- 本机跑着 RunningHub 网关，默认监听 `http://127.0.0.1:6888`。
- 网关 Key。明文 HTTP 只允许本机回环地址；带 Key 时不会向私网地址发送。

## 用法

**侧栏工作室**：选工作流 → 看 `runninghub_describe` 拿到的参数（分辨率字段、参考素材槽、LoRA 库）→ 填提示词 → 提交。任务在后台轮询，不阻塞聊天；面板里能看到排队 / 运行 / 下载 / 失败的状态，下载失败可以只重下；需要重做时在任务历史里点「重新生成」。

**重新生成**：每个任务提交时，宿主会把这次可重放的输入（提示词、分辨率、片长、自定义参数和参考素材）另存到本机 `replays/`。任务历史里已结束的卡片会有「重新生成」，按原样新建一个任务并重新计费；新任务同样会进入历史、继续轮询。参考素材按内容哈希去重，不写进任务记录，也不会经接口下发给浏览器。旧版本提交、没有快照或快照已损坏的任务显示禁用的「重新生成」并注明原因；只有保存了快照的新任务才有可点按钮。重新生成只使用原任务的输入，与面板当前选中的工作流和参数无关。

**参考素材**：工作流声明的图片 / 音频槽可以直接预览，素材由宿主从网关拉取后经同源路由转给浏览器，网关地址和 Key 不出服务端。每个已启用的槽位还能点「从图库选 / 从音频库选」，直接列 6888 的常用图库 / 常用音频库：主面板选中的素材只覆盖本次生成，设置抽屉里选中的会写回该工作流的默认素材（与在客户端里选同一份）。原图同样由宿主代理取回，仍受单文件 10MB、请求 25MB 的上限；超过 10MB 的库内素材会在选择器里标灰。

**设置与 6888 互通**：面板右上角「设置」抽屉里现在有该工作流的完整生成设置：分辨率、片长、自定义参数、模型字段（LoRA / 候选组）、随机种子、默认参考素材（图片 / 音频，可清除、可开关旁路槽），以及「绑定当前对话轮次」。这些设置不再需要点保存：改动后会自动写回网关的 `/api/workflows/:alias/defaults`、`/duration`、`/seed`、`/model-field`、`/reference-slots`；这些正是 6888 管理页「单镜生成」读写的那一份，端口调用和 admin 会同时生效。客户端那边改了，插件会自己跟上：面板可见时每 5 秒轮询，面板收起时后台每 15 秒重读工作流列表，工作流 `revision` 变了就重建提示词模板与素材清单，不需要点「同步客户端」（那个按钮只是立刻刷新一次的快捷方式）。生成永远套用客户端当前设置，插件不再保留「应用工作流默认值」这类会分叉的开关。插件只把 Key 留在 DSH 凭据服务里，不写进设置。管线工作流的素材属于子工作流，插件保存时会保留原组，不会清空。

**自动插入**：打开发言框上方的自动插入后，**每回合都会自动出片，不需要玩家额外说“生成视频”**：写正文时模型先在思考里定稿完整正文，再按设置的数量挑出最精彩的瞬间，用 `runninghub_generate` 把每段视频提交出去（可带 `anchor` 指定插在哪句之后），然后**在同一条回复里**调用 `submit_story` 提交同一份完整正文（必须是最后一个工具调用），不要在视频工具返回后再补正文——分两步提交时，第二次模型请求可能被上游内容审核整条拒绝（`PROHIBITED_CONTENT`），结果是视频已花积分提交、正文却没有。成片完成后自动补到这一轮正文里。每回合提交几段由「设置 → 正文视频 → 每回合生成视频段数」决定（1–10，默认 3）；改完后下一轮提示词就会按新数量要求模型拆分镜。模型只提交、不等出片。宿主提供生成身份接口时绑定到本次生成；没有该接口的旧宿主退回到「等这一轮结算再绑定」，不会挂到上一轮的正文上。宿主能识别生成身份时，生成候选或后台任务会拒绝自动插入；自动插入关闭时，模型调用 `runninghub_generate` 会被宿主直接拒绝，面板手动生成不受影响；需要出片时关掉自动插入用侧栏工作室。先图片后视频的管线（首帧、四宫格故事板等）只把成片视频挂进正文，中间图只留在任务历史里供面板预览；旧版本已经同时挂上的中间图会在下一次对账时移除。

**非工具调用模式（正文标记）**：面板「设置 → 正文视频 → 生成方式」可以切到「正文标记」。开启后：

- 宿主不再要求模型调用 `runninghub_generate`，并把 RunningHub 的四个工具（`runninghub_describe` / `runninghub_generate` / `runninghub_status` / `runninghub_send_pregenerated`）全部从请求里撤掉；模型只写正文和正文末尾的标记块。
- 模型按下面的格式把每个镜头的提示词写进正文；宿主在这一轮结算时解析标记块，按 `@after` 的句子挂上「生成中…」的插件媒体占位，随后提交任务。成片下载完成后，占位会原地换成视频 / 图片。
- 标记块的清理交给 Tavern 的全局正则库，不再调用 `editTurn`：插件加载时会往 `<tavern data>/tavern-extension-settings.json` 的 `regex` 数组写两条规则（`dsh-runninghub-marker-strip` 收闭合块，`dsh-runninghub-marker-strip-open` 收漏写结束行的块），名称都以「RunningHub · …（自动管理）」开头，作用位置是「AI 输出」。Tavern 的显示投影和提示词投影都会过这两条规则，所以正文区、正文存档投影和下一轮上下文里都不会出现提示词。
- 插入位置不额外写文本标记：插件媒体项本身锚定在 `@after` 那一句所在段落后，播放器、重生成和任务历史沿用现有能力。
- 因为走的是正则投影而不是正文编辑，标记块跨进 HTML 块、块内出现 `<Picture N>` / `<Subject N>` 尖括号标签都能整段移除；模型不需要转义，也没有「HTML 块要保持原样」的限制。
- 需要同时开启「视频完成后自动插入」和「总是发送当前工作流的提示词模板」。切到正文标记模式时插件会先确认正则库写得进去，写不进去就拒绝切换，避免提示词漏进正文。Tavern 自己的「输出走工具调用」可以保持关闭；如果开着，模型会把正文和标记块一起放进 `submit_story` 的 `content`，标记仍然有效。
- **流式预提交**（设置 → 正文视频 → 「正文写完前就提交」，默认关闭）：打开后插件在正文**逐字生成时**就用 Tavern 的 `watchReply` 读正在写的回复，只要出现写完的 `[[RH:SHOT]]` 块，立刻把镜头交给宿主提交，不再等「正文写完 + 后台结算结束」。宿主侧没有流式事件（`onTurnSettled` 是正文写完且结算结束后才触发，`getTurn` / `getHistory` 对生成中、结算中的最新一轮返回 `null`），所以这一步只能由网页侧发起到同源接口 `action: preclaim`。幂等靠「同一局 + 同一轮 + 提示词指纹（`@prompt`/`@image`/`@video` 的 FNV-1a）」算出的 `requestId`：结算时同一块算出同一个 ID，`submitJob` 直接复用已有任务，网关只收一次费。预提交发生在正文版本确定之前，所以这一轮被重写、回退或块被删掉时，已经提交的镜头仍会计费——它会被解除绑定，只留在任务历史里，不会插进正文；半截块（没有 `[[/RH:SHOT]]`）永远不提交，格式与当前工作流对不上（单段写了 `@image`+`@video`、管线缺段）也不提交，留给结算挂失败占位。正文或标记块走 `submit_story` 的工具参数时网页侧读不到，仍按结算后的正常路径提交。
- 原始存档（`sourceText`）里仍保留标记块，方便排查；玩家看到和模型读到的都是投影后的文本。这两条规则由插件维护，在 Tavern 正则库里手改或停用会被下一轮（以及下次启动）改回来。插件卸载后规则仍留在库里并保持启用，历史正文继续隐藏标记块；不需要时在 Tavern 正则库里手动停用或删除。
- 旧存档里已经写进正文的标记块不会自动重写：当时保存的上下文文本仍带着提示词，直到被压缩掉；重新读取的显示会按当前正则正常隐藏。

格式（正文末尾，多个镜头就重复多个块）：

```text
[[RH:SHOT]]
@after
正文里紧挨插入位置的一句原句（逐字复制；省略则附在正文末尾）
@caption
可选，短镜头名
@prompt
单段工作流的完整提示词（文生图 / 文生视频 / 图生视频都用这一段）
[[/RH:SHOT]]
```

两段式管线（Qwen 多图生图 → 图生视频、首帧管线等）把 `@prompt` 换成两段，宿主分别落到 `custom.image_prompt` 与 `prompt`：

```text
[[RH:SHOT]]
@after
她走进门。
@image
Qwen 多图生图：《image1》中的女子站在雨夜的门口……
@video
The woman steps through the door, camera pushes in……
[[/RH:SHOT]]
```

字段规则：

- 块开始 / 结束必须是 `[[RH:SHOT]]` 与 `[[/RH:SHOT]]`；全角括号、大小写和字段后的冒号都能识别。
- `@after`、`@caption`、`@prompt`、`@image`、`@video` 单独占一行；字段内容可以换行，提示词里不要出现单独成行的这些字段名。
- 单段工作流只写 `@prompt`；管线必须同时写 `@image` 和 `@video`。块统一放在正文最后，块外不要再写一遍提示词。
- 宿主只处理最新一轮，且必须在提示词模板可用、网关已配置时提交；格式错误的块仍会从正文移除，并挂一条失败占位说明原因，不会白花积分。
- 正文标记模式下预生成池不进入提示词，也不会自动补池；仍可在「预生成」页手动补池并发送到本轮。

**视频缩略图与播放器**：PC 宽面板下任务历史是缩略图网格：视频 / 图片占一张 16:9 大缩略图，底部只留标题、时间、费用和一个很小的「重新生成」；失败任务单独收进紧凑的「异常任务」列表，不再占大卡片。面板右下角弹出同款缩略图的完成通知（只对面板打开后新完成的任务生效，刷新页面不会给历史结果补弹）。点任务卡缩略图、通知缩略图或「播放」按钮打开灯箱播放器，`Esc` / 遮罩 / × 均可关闭，关闭后焦点回到触发按钮。通知最多同时显示 3 条、不自动收起；在「单镜生成」页会抬到固定提交栏上方，避免盖住「开始生成」。播放器底部只接现有能力：「重新生成」（有可重放输入时）和「关闭」，不新增下载动作。标题使用工作流别名，因为任务摘要不含提示词；需要「山湖空镜」这类场景标题时，得由宿主另补一个短标题字段。

**预生成视频池**：侧栏工作室的「预生成」页按**每一局**配置目标数量（0–20）、每轮最多补几条、就绪满几轮没用自动退出、以及每轮是否复审。开启后，每轮正文结算完，宿主用这局 Tavern 的**后台模型**读最近剧情和当前工作流的提示词模板，预判接下来最可能出现的画面，写好成品提示词后直接提交到 RunningHub。就绪的备用视频列进正文提示词，模型需要发视频时先用 `runninghub_send_pregenerated` 从池里挑一条贴合的——不花积分、立刻到，用掉后下一轮自动补。没有贴合的才照常 `runninghub_generate`。

预生成会自动花积分：目标数量 > 0 即视为授权后台提交。首次使用前请确认已配置 Tavern 的默认后台模型；规划失败会冷却 10 分钟，面板里「补池」可手动重试（不受冷却限制）。池子只保存在本机（`pregen/`，按 `gameId` 分文件），不阻塞正文，也不会因为刷新页面而丢失。

**工作流由面板决定，模板直接发送**：侧栏面板里选中的工作流会写回宿主并全局保存，模型不再选择、猜测或传递工作流别名。选中后宿主读取该工作流的提示词模板（网关的 `defaultEnhanceMode` / `port-directive`），**直接切段注入正文提示词**（Tavern 单段上限 8000 字，模板通常更长），不再写 Tavern Skill，也不让模型多一步「先读 Skill」。面板「设置 → 生成行为」里的**「总是发送当前工作流的提示词模板」默认开启**：每轮都把完整模板发给模型，切换工作流后下一次请求自动换新；关掉后不发送模板，`runninghub_generate` 会被明确拒绝，面板手动生成不受影响。自动插入只决定成片要不要自动补回正文，与模板发送相互独立。全参考工作流（`h3-ref2va` / `h3-hybrid`）在提交前仍校验六段结构和 `<Subject N>`，缺段直接拒绝，避免拿散文提示词白花积分；面板手动提交不拦，方便试参数。`runninghub_generate` 用结构化参数：管线工作流的 `input.prompt` 是视频段、`input.image_prompt` 是生图段，宿主直接写进 `custom.image_prompt`；不需要 `image###` / `video###` 标记（旧标记仍兼容）。没有选择工作流时生成会明确报错，而不是回退到模型猜的别名。管线取模板时会把生图侧 / 视频侧的默认素材标签与上限一并带给网关（Qwen 多图管线缺 `<imageN>` 清单会 400），而且按这一单真正接得上的素材编号：四宫格管线 `videoRefSource=image` 时视频只接四片（`<Picture 1>`～`<Picture 4>`，视频工作流自己的设定图这一单被顶掉），`videoRefSource` 为 video 或缺省时才是设定图占前两个编号、四片顺延——两种口径与生成端 `pipeline.ts` 一致，模型不会写出多于实际图片的编号被 `strict_prompt_tags` 整单拒收；模板校验失败（400）会自动回退到不依赖参考图的同媒介模板，模板确实不可用时只跳过视频、不中断本轮正文。

**模型工具**：

| 工具 | 作用 |
|---|---|
| `runninghub_describe` | 读面板当前选中工作流的参数与参考素材槽，不能改选，不提交任务 |
| `runninghub_generate` | 为面板当前工作流提交一个图片 / 视频任务，立即返回；不确定时用同一个 `request_id` 重试 |
| `runninghub_status` | 查本地任务历史，只查不提交 |
| `runninghub_send_pregenerated` | 把预生成池里一条就绪视频发进本轮正文（可带 `anchor` / `caption`），不花积分；一条只能发一次 |

任务与绑定关系保存在 DSH 数据目录的 `profile-data/tavern/data/runninghub/`（`tasks/` 存任务状态，`replays/` 存可重放输入与参考素材，`bindings/` 存插入位置，`pregen/` 存每局的预生成池）。任务记录仍然不含 prompt 和 base64；可重放输入单独存放（目录 0700 / 文件 0600），只供「重新生成」使用。重启后会继续对账：已知远端任务只查询、不重提，`submit_unknown` 也不会被自动重新提交；预生成池里正在生成、有任务号的条目会接着等片，中断在提交途中的标失败、不重提。

## 开发

`client.js` 是浏览器侧的产物，直接维护，没有构建步骤。

```sh
npm test              # 零依赖单测
npm run test:ui       # 可选界面测试，需 DSH_UI_DEPS=<dsh-tavern>/package.json
npm run test:runtime  # 需要 DSH_BOOT_MODULE=<DSH 运行时>/lib/node_modules/@deepseek-ai/dsh-app-boot/lib/index.js
```
